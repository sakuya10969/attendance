# プロダクト概要

勤怠管理SaaS。マルチテナント対応のWebアプリケーション。
企業ごとにテナントを分離し、従業員の出退勤・休暇・承認・締め処理を一元管理する。

## 主要機能

- 出退勤打刻（日跨ぎ勤務対応）
- 休憩管理
- 打刻修正・申請・承認フロー
- 休暇申請・承認
- 締め処理
- 勤怠一覧・集計
- テナント管理（作成・停止・再開）
- ユーザー管理（テナント内）
- 部署・勤務形態・休日・承認フロー・締め設定の管理
- 監査ログ閲覧（全体 / テナント内）

## ロール設計

3つのロールスコープを持つ。ロールはアプリ側DB（PostgreSQL）で管理する。

### system_admin（システム管理者）
- 全テナントを横断して管理
- テナントの作成・停止・再開
- 初期テナント管理者の設定（テナント作成時に指定）
- 全体監査ログの閲覧
- 最初の system_admin はGUIから作成しない（CLIスクリプトで作成）

### tenant_admin（テナント管理者）
- 自テナント内のユーザー管理
- 部署・勤務形態・休日・承認フロー・締め設定の管理
- テナント内監査ログの管理

### tenant_user（テナントユーザー）
- 打刻（出勤 / 退勤）
- 打刻修正申請
- 休暇申請
- 自身の勤怠データ閲覧

## 画面設計方針

- フロントエンドは1つのアプリとして構成する（分割しない）
- ロールごとにルーティングと機能を分離する
  - `/system/*` — system_admin 向け
  - `/admin/*` — tenant_admin 向け
  - `/app/*` — tenant_user 向け
- ロールに応じてナビゲーション・画面・操作可能範囲を制御する
- 権限外のルートへのアクセスはガードで弾く

## マルチテナント

- 主要テーブルに `tenant_id` を持たせてデータ分離
- Firebase Auth の uid をそのまま業務モデルに直結させず、アプリ独自の user テーブルを持つ
- テナント作成時に初期テナント管理者を指定可能（GUIから操作）
  - バックエンドで Firebase Admin SDK によるユーザー作成/取得 → user作成 → tenant紐付け → tenant_admin ロール付与

## 認証・認可方針

- Firebase Auth は認証のみ担当
- 認可・ロール・テナント所属は PostgreSQL で管理する（正本）
- Firebase custom claims は補助的にのみ使用する（正本にしない）
- バックエンドで firebase-admin により IDトークンを検証後、アプリ独自の user/tenant/role にマッピング

## 初期システム管理者（ブートストラップ）

- 最初の system_admin は `scripts/create-system-admin.ts`（NestJSスクリプト）で作成する
- GUIに依存しないブートストラップ手段
- スクリプト仕様:
  - Firebase Admin SDK でユーザー作成 or 取得
  - PostgreSQL に user 作成
  - system_admin ロール付与
  - 冪等性を持つ（既存ユーザーがいる場合は再利用、重複作成を防ぐ）
  - 必要に応じて custom claims を同期可能
- NestJS の ApplicationContext を利用し、Service 経由で処理する（直接DB操作しない）
- 用途: 初回環境構築・本番初期化・障害復旧

## 日付・時刻方針

- DB保存: UTC
- 画面表示・業務ロジック: JST考慮
- 勤怠システムで扱う時刻要素:
  - 出勤 / 退勤
  - 休憩
  - 日跨ぎ勤務
  - 締め日
  - 深夜時間（22:00–5:00）
  - 所定休日 / 法定休日

## 監査ログ

- 勤怠システムでは監査ログが重要
- 記録対象:
  - 打刻修正（誰が、いつ、何を変更したか）
  - 承認 / 差し戻し
  - 締め処理の実行
  - テナント作成・停止・再開
  - ユーザー作成・ロール変更
- system_admin は全体監査ログを閲覧可能
- tenant_admin は自テナント内の監査ログを閲覧可能
