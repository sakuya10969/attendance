# プロジェクト概要

## 概要

勤怠管理SaaS。マルチテナント対応のWebアプリケーションとして、企業ごとにテナントを分離し、従業員の出退勤・休暇・承認・締め処理を一元管理する。

## 背景・目的

- 中小〜中堅企業向けに、導入コストの低いクラウド型勤怠管理を提供する
- テナント分離により、1つのアプリケーションで複数企業を安全にホスティングする
- 打刻・申請・承認・締めの業務フローをデジタル化し、管理工数を削減する

## 主要機能

- 出退勤打刻（日跨ぎ勤務対応）
- 休憩管理
- 打刻修正・申請・承認フロー
- 休暇申請・承認
- 締め処理（月次）
- 勤怠一覧・集計
- テナント管理（作成・停止・再開）
- ユーザー管理（テナント内）
- 部署・勤務形態・休日・承認フロー・締め設定の管理
- 監査ログ閲覧（全体 / テナント内）

## ロール

| ロール | スコープ | 主な操作 |
| --- | --- | --- |
| system_admin | 全テナント横断 | テナントCRUD、全体監査ログ、初期管理者設定 |
| tenant_admin | 自テナント内 | ユーザー管理、各種設定、テナント内監査ログ |
| tenant_user | 自身のデータ | 打刻、修正申請、休暇申請、勤怠閲覧 |

## 画面構成

- 1つのSPAとして構成（分割しない）
- ロール別ルーティング: `/system/*`, `/admin/*`, `/app/*`
- ルートガード + ナビゲーション制御でロールに応じた画面を提供

## 認証・認可

- 認証: Firebase Auth（IDトークンベース）
- 認可: アプリ側DB（PostgreSQL）でロール・テナント所属を管理
- Firebase custom claims は補助的利用のみ

## 日付・時刻

- DB: UTC保存
- 表示・業務ロジック: JST考慮
- 深夜時間帯（22:00–5:00）、日跨ぎ勤務、締め日を扱う

## 初期セットアップ

- 最初の system_admin は `scripts/create-system-admin.ts` で作成（GUI非依存）
- テナント作成時に初期 tenant_admin をGUIから指定可能
